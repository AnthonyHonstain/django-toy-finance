# django-finance

Really just a toy repo to practice more applied programming problems in an
interview context (so working on problems in a time bounded window).

A Python 3.13 interview-practice workspace for financial and subscription
ledger problems. The repository retains a small Django project shell, but the
practice exercises are plain in-memory Python modules tested with pytest. See
[`finance/README.md`](finance/README.md) for the exercise layout and workflow.

NOTE - this is a Django project, but I have never really done much of consequence wrt
Django in there, that might change in the future, but just leaving it for now.

## Environment setup

The existing local workflow uses a micromamba environment with Poetry managing
the project dependencies:

```shell
micromamba create -n django-finance -c conda-forge python=3.13
micromamba activate django-finance
python -m pip install poetry
poetry install --no-root
```

Once the environment is active, invoke Python tools with `python -m ...`. This
ensures they run from the active environment instead of an unrelated global
installation.

## Tests and checks

Run the full pytest suite:

```shell
python -m pytest -q
```

The clean scaffold baseline is `58 passed, 13 skipped`: three skips preserve
the unfinished Phase 3 scenarios from the May subscription run, and ten skips
belong to the new September practice run.

The tests use pytest-style classes and assertions. Do **not** use
`python manage.py test`: Django's unittest runner does not collect these test
classes.

Run an individual practice exercise while working:

```shell
python -m pytest -q \
  finance/tests/subscription_ledger_2026_09_13_01
```

Run the remaining checks with:

```shell
python -m mypy .
python -m black --check .
python manage.py check
```

Apply Black formatting with:

```shell
python -m black .
```

If you prefer Poetry's managed virtual environment, first run
`poetry install --no-root`, then prefix the same commands with `poetry run`.

## Practice-run convention

Each attempt has a dated implementation package under `finance/` and a
matching test package under `finance/tests/`. A new exercise starts with its
scenario tests skipped. Remove one `@pytest.mark.skip` marker at a time, write
the smallest implementation that makes that scenario pass, and continue
incrementally.

The older `finance/tests.py` generated by `startapp` was removed because the
repository now uses the `finance/tests/` package. Keeping both creates an
ambiguous `finance.tests` import during Django test discovery.

## Optional Django shell

Django currently provides the project shell and admin route; the interview
exercises do not depend on Django models, migrations, or the development
server. If you want to run the shell anyway:

```shell
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 8002
```

The equivalent Gunicorn command is:

```shell
gunicorn --bind 0.0.0.0:8002 finance_service.wsgi:application -w 1
```
